## Built for Production Excellence

::feature-boxes
:::feature-box{tag="Kubernetes" title="Native Kubernetes Lifecycles"}
Dedicated probe server running on port 8001 with `/startup`, `/alive`, and `/ready` endpoints. Prevents pod restarts during long database migrations and automatically sheds Ingress traffic under queue congestion.
:::

:::feature-box{tag="Security" title="Fast-404 Security Shield"}
Instantly drops automated scanners (probing for `.php`, `/.env`, `/wp-admin/`) at the gateway in microseconds. Protects Django middleware, session caches, and database connection pools from bot scans.
:::

:::feature-box{tag="DoS Protection" title="Token-Bucket Rate Limiter"}
Gateway rate limiting with client IP extraction via `X-Forwarded-For` for Kubernetes Ingress and load balancers. Silently drops volumetric floods with zero log spam to prevent log-based Denial of Service.
:::

:::feature-box{tag="Observability" title="Prometheus Metrics"}
Built-in `/metrics` exposition scraping request counts, latency averages, and queue depth. POSIX shared memory buffers aggregate cross-worker state atomically with sub-microsecond overhead.
:::

:::feature-box{tag="Architecture" title="Zero-Config WSGI & ASGI"}
Drop into your existing project with `python manage.py serve`. Hurricane auto-detects `WSGI_APPLICATION` or `ASGI_APPLICATION` from your Django settings without complex config files.
:::

:::feature-box{tag="Automation" title="Lifecycle Webhooks"}
Asynchronous webhook dispatches notifying monitoring services, Slack, or orchestrators when pods complete startup, experience deadlock health failures, or initiate graceful termination.
:::
::

## The Django + Kubernetes Advantage

Django was developed with a batteries-included philosophy and gracefully handles complex web application challenges. However, modern infrastructure requires cloud-native patterns: ephemeral containers, dynamic autoscaling, and real-time health feedback.

### It's Not Just About Running in a Cluster
Anyone can run Django in a container behind Gunicorn. But Kubernetes requires more:
- **Migration Synchronization:** Database migrations run during pod startup must not be slain by aggressive readiness timers.
- **Traffic Shedding:** When a pod's worker queue is temporarily saturated, Kubernetes should divert traffic to siblings rather than terminating the container.
- **Deadlock Detection:** When worker threads hang on an unresponsive database socket, the server should signal the kubelet to restart the container automatically.
- **Edge Attack Immunity:** Automated bot vulnerability scans (`wp-login.php`, `.env`) should never consume Django database connections or worker threads.

Hurricane solves these architectural friction points directly at the server layer, giving your Django applications the reliability and resilience required in modern cloud platforms.

## Quickstart

### 1. Install Hurricane
```bash [Astral uv]
uv add django-hurricane
```

```bash [pip]
pip install django-hurricane
```

### 2. Add to `INSTALLED_APPS`
```python [settings.py]
INSTALLED_APPS = [
    # Standard Django apps...
    "django.contrib.admin",
    "django.contrib.auth",
    # ...
    # Add Hurricane:
    "hurricane",
]
```

### 3. Launch Your Server
```bash
python manage.py serve
```
