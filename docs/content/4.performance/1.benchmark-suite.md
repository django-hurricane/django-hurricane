# Hurricane Performance Benchmark Suite

To measure real-world concurrency, latency distributions, and container scaling characteristics under synthetic load, we created the **[Django Hurricane Benchmark Suite](https://github.com/django-hurricane/django-hurricane-bench)** on GitHub.

The suite evaluates **`django-hurricane`** (targeting version `2.0.0rc1` and newer releases powered by [Granian](https://github.com/emmett-framework/granian)'s Rust runtime) against PostgreSQL 17, upstream microservices, complex template rendering, and session authentication.

---

## Architecture Overview

The benchmark infrastructure uses Docker Compose to orchestrate isolated container environments driven by headless Locust step-load testing:

```
                                            +------------------------+
                                            |   Locust Load Runner   |
                                            |   (Headless Step-Load) |
                                            +-----------+------------+
                                                        |
                         +------------------------------+------------------------------+
                         |                              |                              |

             [ Flavors 1 & 2: WSGI ]        [ Flavor 3: ASGI-Sync ]       [ Flavors 4, 5 & 6: ASGI ]
             Hurricane WSGI Mode            Hurricane ASGI Mode           Hurricane ASGI Mode

                         |                              |                              |
                         +------------------------------+------------------------------+
                                                        |
                                                        v
                                              +--------------------+
                                              | PostgreSQL 17 (DB) |
                                              | (Real Database)    |
                                              +--------------------+
```

## The 6 Evaluated Deployment Paradigms

The suite compares six distinct deployment paradigms across Hurricane's runtime engines:

1. **WSGI (Worker=1 / Single Thread)**: Hurricane WSGI mode with `--workers 1` (strict single-threaded baseline for 1-to-1 comparison with single-process event loop).
2. **WSGI (Auto Threads / Multi-Thread)**: Hurricane WSGI mode with auto-threads calculation `min(32, cpu_count + 4)` threads (traditional production multi-threaded WSGI deployment).
3. **ASGI (Forced Sync Views)**: Hurricane ASGI mode running standard synchronous Django views, demonstrating the exact penalty of Django's `sync_to_async(thread_sensitive=True)` adapter under load.
4. **ASGI (Clean Async / Single Thread)**: Hurricane ASGI mode with clean async views (`async def`), pooled `httpx` async HTTP client, and `--workers 1`.
5. **ASGI (Auto Threads / Clean Async)**: Hurricane ASGI mode with clean async views and Hurricane's auto-threads calculation `min(32, cpu_count + 4)` threads for non-blocking threadpool dispatch and template rendering.
6. **ASGI + `django-async-backend`**: Hurricane ASGI mode paired with [django-async-backend](https://github.com/Arfey/django-async-backend) utilizing true non-blocking `psycopg 3` async connection pooling via `Product.async_objects` on the Tokio event loop.

## Workload Routes

The test application exercises seven realistic traffic paths reflecting modern production architectures:

| Route | Feature Area | Concurrency Characteristic |
| :--- | :--- | :--- |
| `POST /api/auth/login` | Session & Auth Middleware | Cookie signing, session read/write, user credentials validation. |
| `GET /api/auth/me` | Session Verification | Native async session verification (`auser` under ASGI). |
| `GET /catalog/render` | Complex Template Rendering | Django Template Language (DTL) overhead, nested loops, filters, context processors. |
| `GET /api/items` & `POST /api/items` | JSON API Serialization | JSON parsing, model validation, and bulk ORM queries. |
| `GET /external/fetch` | Unreliable Upstream API | Interacts with a mock upstream API (`fake-api` with randomized latency) simulating third-party network delays. |
| `GET /catalog/search` | Database Queries & Aggregations | Filtering, foreign key joins (`select_related`), and statistical aggregations on PostgreSQL 17. |
| `GET /api/gateway/aggregate` | Scatter-Gather Microservices API Gateway | Fan-out to 3 microservices: sequential blocking in WSGI vs `asyncio.gather()` parallel sockets in ASGI. |

## Reproducing the Benchmarks Locally

Clone the repository and run the automated execution suite:

```bash
git clone https://github.com/django-hurricane/django-hurricane-bench.git
cd django-hurricane-bench

# Run full sequential benchmark across all 6 flavors:
./scripts/run_benchmark.sh

# Target a specific Hurricane version and concurrency parameters:
HURRICANE_VERSION=2.0.0rc2 BENCH_USERS=150 BENCH_DURATION=45s ./scripts/run_benchmark.sh
```

For continuous testing, the suite also runs in GitHub Actions via `workflow_dispatch`, automatically archiving reports under `archive/` upon completion.
